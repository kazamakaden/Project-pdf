# คู่มือติดตั้งและส่งมอบระบบ

**ระบบพัสดุสำนักงาน & ใบขออนุมัติสั่งซื้อ — วิทยาลัยเทคนิคอุดรธานี**

> เอกสารนี้สำหรับ **ผู้ดูแลระบบ / นักพัฒนา / คนที่จะรับช่วงดูแลเว็บต่อ**
> หากต้องการแค่วิธีใช้งานทั่วไป ให้อ่าน [คู่มือผู้ดูแลระบบ](./คู่มือผู้ดูแลระบบ.md)

## 1. ภาพรวมสถาปัตยกรรม

```
[เบราว์เซอร์ผู้ใช้]
      │  เปิดเว็บ (React SPA)
      ▼
[Netlify]
   ├── Static site (โฟลเดอร์ dist/)  ← หน้าเว็บทั้งหมด
   └── Netlify Functions  /api/products, /api/personnel  ← API (TypeScript)
              │  mongodb driver
              ▼
      [MongoDB Atlas]
        database: udtc
        collection: products, meta, personnel
```

| ส่วน | เก็บที่ไหน |
| --- | --- |
| สินค้า / รูปสินค้า | MongoDB Atlas (ฐานข้อมูลกลาง) |
| ทำเนียบบุคลากร | MongoDB Atlas (`personnel`) |
| ตะกร้าสินค้า, ธีม, สถานะล็อกอิน | `localStorage` ของเบราว์เซอร์แต่ละคน |
| ข้อมูลตั้งต้น 252 รายการ | ไฟล์ `src/data/products.ts` (ฝังมากับเว็บ) |
| API สินค้า | `netlify/functions/products.ts` (เสิร์ฟที่ `/api/products`) |
| API ทำเนียบบุคลากร | `netlify/functions/personnel.ts` (เสิร์ฟที่ `/api/personnel`) |

**จุดสำคัญ:** หน้าเว็บและ API อยู่ **โดเมนเดียวกัน** จึงไม่ต้องตั้ง CORS และ deploy จบใน Netlify ที่เดียว

## 3. รันบนเครื่อง (Local Development)

```bash
npm install
copy .env.example .env    # แล้วแก้ค่าด้านใน (Windows) / cp .env.example .env (macOS/Linux)
npm run dev               # เปิด http://localhost:5173
```

| คำสั่ง | ใช้ทำอะไร |
| --- | --- |
| `npm run dev` | เปิดเว็บ + API `/api/*` บนเครื่อง (มี dev plugin ให้อัตโนมัติ) |
| `npm run build` | ตรวจ TypeScript แล้ว build ลง `dist/` |
| `npm run preview` | เปิดดูไฟล์ที่ build แล้ว |
| `npm run typecheck` | ตรวจ TypeScript ทั้งฝั่งเว็บและฝั่ง API |
| `npm run smoke` | ทดสอบหน้าเว็บจริงอัตโนมัติ (30 กรณี) |

**กรณีไม่มี `MONGODB_URI`:** ระบบจะเก็บสินค้าไว้ที่ไฟล์ `.local-db/products.json` และทำเนียบบุคลากรที่
`.local-db/personnel.json` ในเครื่อง (เฉพาะโหมด dev) เพื่อให้ลองเพิ่ม/แก้/ลบได้ครบทุกปุ่มโดยไม่ต้องต่อฐานข้อมูลจริง

## 4. Environment Variables (ตัวแปรสภาพแวดล้อม)

> 🔒 **ความลับต้องไม่ขึ้นต้นด้วย `VITE_`** เพราะค่าที่ขึ้นต้นด้วย `VITE_` จะถูกฝังลงไฟล์ JS ที่ผู้ใช้ดาวน์โหลดได้

| ชื่อ | ฝั่ง | จำเป็น | ค่า / ใช้ทำอะไร |
| --- | --- | --- | --- |
| `VITE_GOOGLE_CLIENT_ID` | เว็บ | ✅ (ถ้าใช้ Google Login) | Client ID จาก Google Cloud |
| `VITE_ADMIN_EMAIL` | เว็บ | ✅ | อีเมล Google ของแอดมิน (ใช้ตรวจสิทธิ์ฝั่งหน้าเว็บ) |
| `VITE_API_URL` | เว็บ | ❌ | ที่อยู่ API ถ้าแยกโดเมน (ปกติเว้นว่าง) |
| `MONGODB_URI` | เซิร์ฟเวอร์ | ✅ | connection string ของ MongoDB Atlas |
| `MONGODB_DB` | เซิร์ฟเวอร์ | ❌ | ชื่อฐานข้อมูล (เว้นว่าง = `udtc`) |
| `ADMIN_EMAIL` | เซิร์ฟเวอร์ | ✅ | อีเมลแอดมินที่ API ยอมรับ (เว้นว่าง = ใช้ `VITE_ADMIN_EMAIL`) |
| `GOOGLE_CLIENT_ID` | เซิร์ฟเวอร์ | ✅ | Client ID สำหรับตรวจ ID token (เว้นว่าง = ใช้ `VITE_GOOGLE_CLIENT_ID`) |

**ตัวอย่างไฟล์ `.env` สำหรับรันบนเครื่อง:**

```env
VITE_GOOGLE_CLIENT_ID=xxxxxxxxxxxx.apps.googleusercontent.com
VITE_ADMIN_EMAIL=owner@gmail.com

MONGODB_URI=mongodb+srv://user:password@cluster0.xxxxx.mongodb.net
MONGODB_DB=udtc
ADMIN_EMAIL=owner@gmail.com
GOOGLE_CLIENT_ID=xxxxxxxxxxxx.apps.googleusercontent.com
```

> ⚠️ ไฟล์ `.env` ถูกใส่ใน `.gitignore` แล้ว — **ห้าม commit** ขึ้น Git เด็ดขาด

**ค่าตั้งต้นของระบบ** (ถ้าไม่ตั้ง env เลย ระบบจะใช้ค่านี้):
- อีเมลแอดมิน: `admin@udtc.ac.th` (ดู `src/config/site.ts`)
- ชื่อฐานข้อมูล: `udtc`

## 5. ตั้งค่าฐานข้อมูล MongoDB Atlas

1. เข้า https://cloud.mongodb.com → สร้าง **Cluster** (เลือกแพ็กเกจฟรี **M0** ก็พอ)
2. เมนู **Security → Database Access** → **Add New Database User**
   - ตั้ง username / password (จดไว้ให้ดี — ต้องใช้ใน connection string)
   - Role: **Read and write to any database**
3. เมนู **Security → Network Access** → **Add IP Address**
   - สำหรับ Netlify แนะนำใส่ `0.0.0.0/0` (อนุญาตทุก IP) เพราะ IP ขาออกของ Netlify เปลี่ยนได้
4. กด **Connect → Drivers** → คัดลอก connection string
   - แบบ `mongodb+srv://...` (แนะนำ)
   - แทน `<password>` ด้วยรหัสจริง และเติม `/udtc` ท้าย host ก่อน `?` ถ้าอยากระบุ DB ตรง ๆ
5. นำค่าที่ได้ไปใส่ `MONGODB_URI` และตั้ง `MONGODB_DB=udtc`

**โครงสร้างฐานข้อมูล:**

| ชื่อ | ชนิด | ใช้ทำอะไร |
| --- | --- | --- |
| `products` | collection | เก็บสินค้าทั้งหมด (รวมรูปเป็น data URL) |
| `meta` | collection | เก็บ marker กันการ seed ซ้ำ (`catalog-seed-v1`) |
| `personnel` | collection | เก็บทำเนียบบุคลากร (`_id`, `name`, `position`, `order`) |

> 💡 **ถ้าเครื่อง/เครือข่ายของคุณบล็อก DNS แบบ SRV** (เจอ error `querySrv ECONNREFUSED`)
> ให้ใช้ **standard connection string** แทน `+srv` สำหรับรันบนเครื่อง เช่น
> ```
> mongodb://user:pass@ac-xxxx-shard-00-00.xxxx.mongodb.net:27017,ac-xxxx-shard-00-01.xxxx.mongodb.net:27017,ac-xxxx-shard-00-02.xxxx.mongodb.net:27017/?tls=true&replicaSet=atlas-xxxx-shard-0&authSource=admin
> ```
> (เอา host ทั้ง 3 ตัว + `replicaSet` จาก Atlas → Connect → *Standard connection string*)
> ส่วนบน Netlify ใช้ `+srv` ได้ปกติเพราะ DNS ที่นั่นรองรับ SRV

## 6. ตั้งค่า Google OAuth (ปุ่ม Sign in with Google)

1. เข้า https://console.cloud.google.com → สร้าง **Project** ใหม่ (หรือใช้ของเดิม)
2. เมนู **APIs & Services → OAuth consent screen** → ตั้งชื่อแอป (External) แล้วบันทึก
3. เมนู **APIs & Services → Credentials → Create Credentials → OAuth client ID**
   - Application type: **Web application**
   - **Authorized JavaScript origins** ใส่:
     - `http://localhost:5173` (สำหรับทดสอบบนเครื่อง)
     - `https://udontechnicalcollege.netlify.app` (โดเมนจริง)
4. คัดลอก **Client ID** (รูปแบบ `xxxx.apps.googleusercontent.com`)
5. นำไปใส่ทั้ง 2 ที่:
   - `VITE_GOOGLE_CLIENT_ID` (ฝั่งเว็บ)
   - `GOOGLE_CLIENT_ID` (ฝั่งเซิร์ฟเวอร์ ใช้ตรวจ token)
6. ตั้ง `ADMIN_EMAIL` + `VITE_ADMIN_EMAIL` เป็นอีเมล Google ของแอดมิน

> ✅ **การตรวจสิทธิ์มี 2 ชั้น:** เบราว์เซอร์ตรวจข้อมูล token (aud/iss/exp/email)
> และ **API ตรวจลายเซ็น token จริงด้วย `google-auth-library`** ก่อนยอมให้บันทึกข้อมูล

## 7. Deploy บน Netlify

ไฟล์ `netlify.toml` ตั้งค่าไว้ให้แล้ว:

| ค่า | ค่าในไฟล์ |
| --- | --- |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node version | `20` |
| SPA redirect | `/*` → `/index.html` |
| Functions | `netlify/functions` → API ที่ `/api/*` |

**ขั้นตอน:**
1. Push โค้ดขึ้น GitHub
2. Netlify → **Add new site → Import an existing project** → เลือก repo (Netlify อ่าน `netlify.toml` เอง)
3. **Site settings → Environment variables** → ใส่ `MONGODB_URI`, `MONGODB_DB`, `ADMIN_EMAIL`,
   `GOOGLE_CLIENT_ID`, `VITE_GOOGLE_CLIENT_ID`, `VITE_ADMIN_EMAIL`
4. กด Deploy → เปิดเว็บหนึ่งครั้ง → ระบบจะ **seed ข้อมูลตั้งต้น 252 รายการ** ให้อัตโนมัติเมื่อฐานข้อมูลว่าง
5. ถ้าแก้ env variable ภายหลัง ต้องกด **Deploys → Clear cache and deploy site** เพื่อให้ค่าใหม่มีผล

**ตรวจว่าระบบต่อฐานข้อมูลได้จริง:**
เปิด `https://<โดเมน>/api/products` ในเบราว์เซอร์ ถ้าเห็น
```json
{"products":[],"count":0,"storage":"mongodb"}
```
แปลว่า **เชื่อมต่อฐานข้อมูลสำเร็จ** (`storage:"mongodb"`) — ถ้า `count:0` คือยังไม่มีข้อมูล ให้กด "นำเข้าข้อมูลตั้งต้น" ในหน้าผู้ดูแล

ตรวจ API ทำเนียบบุคลากรด้วย `https://<โดเมน>/api/personnel` → ต้องได้
```json
{"people":[],"count":0,"storage":"mongodb"}
```

## 8. การเปลี่ยน / ส่งมอบให้แอดมินใหม่

### 8.1 เปลี่ยนแอดมิน (แค่อีเมลคนใหม่ — ใช้ฐานข้อมูลเดิม)
1. Netlify → **Environment variables** เปลี่ยนค่า:
   ```
   ADMIN_EMAIL      = <อีเมล Google ของแอดมินใหม่>
   VITE_ADMIN_EMAIL = <อีเมลเดียวกัน>
   ```
2. **Clear cache and deploy site**
3. ไม่ต้องแตะฐานข้อมูล — แอดมินใหม่ล็อกอินด้วยอีเมลใหม่แล้วแก้สินค้าได้เลย
4. (ถ้าใช้ Google Project ใหม่) เปลี่ยน `GOOGLE_CLIENT_ID` + `VITE_GOOGLE_CLIENT_ID` และเพิ่ม origin ของโดเมนด้วย

### 8.2 เปลี่ยนฐานข้อมูล (เริ่มใหม่ / ย้ายหน่วยงาน)
| วิธี | เปลี่ยนอะไร | ผล |
| --- | --- | --- |
| ใช้ cluster เดิม แต่ DB ใหม่ | `MONGODB_DB=<ชื่อใหม่>` เช่น `udtc2` | collection ใหม่ว่าง ๆ ถูกสร้างให้อัตโนมัติ |
| สร้าง cluster ใหม่ทั้งชุด | `MONGODB_URI=<uri ใหม่>` + `MONGODB_DB` | แยกขาดจากข้อมูลเดิม |

หลังเปลี่ยน เปิดเว็บหนึ่งครั้ง → ระบบจะ seed ข้อมูลตั้งต้น 252 รายการลง DB ใหม่ให้เอง

### 8.3 เปลี่ยนข้อมูลองค์กร (ชื่อ/ที่อยู่/โทร/อีเมล)
แก้ **ไฟล์เดียว** คือ `src/config/site.ts`:
```ts
nameTh, nameEn, tagline, description,
address, phone, fax, email, website, documentFooter
```
ค่านี้ถูกใช้ทั้ง Header, Footer และหัวใบขออนุมัติสั่งซื้อ → แก้แล้ว `npm run build` → push → deploy ใหม่

> **ทำเนียบบุคลากร (ชื่อ/ตำแหน่ง)** ไม่ได้อยู่ในไฟล์นี้ — แอดมินแก้ได้เองที่เมนู “ทำเนียบบุคลากร”
> โดยไม่ต้อง deploy ใหม่ (เก็บใน MongoDB collection `personnel`)

### 8.4 รายการสิทธิ์ที่ต้องส่งมอบให้ผู้รับช่วง (4 ที่)
| # | ระบบ | ต้องให้อะไร |
| --- | --- | --- |
| 1 | **GitHub** | เพิ่มเป็น collaborator หรือโอน repo (`kazamakaden/Project-pdf`) |
| 2 | **Netlify** | เพิ่มเป็น team member ของ site `udontechnicalcollege` |
| 3 | **MongoDB Atlas** | เพิ่มสิทธิ์ใน Organization/Project + บอก username/password ของ DB user |
| 4 | **Google Cloud** | เพิ่มสิทธิ์ใน Project ที่มี OAuth Client ID |

> 🔐 แนะนำให้ **เปลี่ยนรหัสผ่าน MongoDB และ Client ID ใหม่** เมื่อส่งมอบ เพื่อไม่ให้คนเก่ายังเข้าถึงได้

## 9. อัปเดตข้อมูลสินค้าจากไฟล์ Excel

ข้อมูลตั้งต้น 252 รายการแปลงมาจาก `หลิ่มหมงใบเสนอราคาวัสดุสำนักงาน_2570.xlsx` ด้วยสคริปต์ใน `scripts/`:

```bash
node scripts/extract-catalog.mjs   # อ่าน .xlsx -> catalog-raw.json
node scripts/gen-products.mjs      # แปลงเป็น TypeScript -> src/data/products.ts
```

- `extract-catalog.mjs` จะหาไฟล์ `.xlsx` ในโฟลเดอร์ปัจจุบันเอง
- `gen-products.mjs` มีกติกาแยกหมวดหมู่ (`RULES`) — แก้ได้ถ้าอยากปรับการจัดหมวด
- หลังสร้าง `src/data/products.ts` ใหม่ ให้ `npm run build` แล้ว deploy (ข้อมูลจะถูกใช้ตอน seed ครั้งแรกของ DB ว่าง)

## 10. ตรวจสอบระบบก่อน deploy

```bash
npm run typecheck    # ตรวจ TypeScript ทั้งเว็บ + API
npm run build        # build production
npm run smoke        # ทดสอบหน้าเว็บจริงอัตโนมัติ (30 กรณี)
```

`npm run smoke` จะรันด้วย Chrome headless (CDP) ตรวจ: ธีมสว่างเป็นค่าเริ่มต้น, โลโก้, ล็อกอินแบบโลคอล,
แคตตาล็อก/ตัวกรองขนาด, เพิ่มสินค้าและยืนยันว่าบันทึกผ่าน API จริง, ข้อมูลคงอยู่หลังรีเฟรช,
ใบขออนุมัติสั่งซื้อ (หัวข้อความสอดคล้องกับนโยบาย + ไม่มีบรรทัด “(ตัวอักษร)”), API/หน้าทำเนียบบุคลากร
และต้องไม่มี console error
